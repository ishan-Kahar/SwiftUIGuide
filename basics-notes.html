SwiftUI Basics — Junior Developer Guide

UIKit se SwiftUI: app start, View, Spacer layout, navigation, property wrappers, chhota app aur cheat sheet. Sirf text aur code, padhne ke liye.

SwiftUI mein tum UI ko describe karte ho ("mujhe upar title, neeche button chahiye"), aur iOS khud usko screen par bana deta hai. UIKit ki tarah constraints, frames ya viewDidLoad mein views add karne ki zaroorat nahi padti.

Is doc ko kaise padhein

Auto Layout tumhe pehle se aata hai, isliye har topic mein UIKit se comparison diya hai. Order mein padho, kyunki aakhir mein ek chhota app (Login → Home → Detail) hai jo saare concepts ek saath use karta hai.

  1. App kaise start hota hai (AppDelegate/SceneDelegate ki jagah kya)
  2. View kya hota hai
  3. Layout: constraints ki jagah Stack + Spacer
  4. Navigation: button click se next screen
  5. Property wrappers: @State, @Binding aur baaki
  6. Chhota app shuru se aakhir tak
  7. UIKit ↔ SwiftUI cheat sheet

Saara code Xcode 15+ aur iOS 17+ ke liye hai. Har code block ko naye SwiftUI project mein paste karke chala sakte ho.

1. App kaise start hota hai

SwiftUI app ek hi file se start hota hai: @main wala App struct. Wahi decide karta hai ki pehla screen (View) kaunsa hoga. AppDelegate, SceneDelegate aur storyboard ki zaroorat nahi hoti.

UIKit mein kya hota tha

  1. main → UIApplicationMain chalta tha → AppDelegate ka didFinishLaunchingWithOptions call hota tha.
  2. SceneDelegate ka scene(_:willConnectTo:) window banata tha.
  3. window.rootViewController = ... set hota tha, ya Main.storyboard ka initial view controller load hota tha.
  4. LaunchScreen.storyboard tab tak dikhta tha jab tak pehla screen ready na ho.

SwiftUI mein kya hota hai

Xcode mein naya project (Interface: SwiftUI) banao. Tumhe sirf do files milengi:

// MyApp.swift  — app ka entry point
import SwiftUI

@main                      // "app yahan se start hoga"
struct MyApp: App {
    var body: some Scene {
        WindowGroup {      // = UIWindow (iPad par multiple windows bhi)
            ContentView()  // = rootViewController, yani pehla screen
        }
    }
}

// ContentView.swift — pehla screen
import SwiftUI

struct ContentView: View {
    var body: some View {
        Text("Hello, World!")
    }
}

#Preview {                 // Xcode canvas mein live preview
    ContentView()
}

Flow simple hai: @main → MyApp → WindowGroup → ContentView ka body → screen par UI.

Launch screen ab kahan hai

Storyboard nahi hota. Target → Info tab mein Launch Screen (UILaunchScreen) key hoti hai. Wahan background color aur image (Assets se) set karte ho. Bas.

AppDelegate phir bhi chahiye ho to

Push notifications ya Firebase setup jaise kaam ke liye AppDelegate ko "jod" sakte ho:

class AppDelegate: NSObject, UIApplicationDelegate {
    func application(_ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions:
        [UIApplication.LaunchOptionsKey: Any]? = nil) -> Bool {
        print("App launch hua")   // Firebase.configure() etc.
        return true
    }
}

@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

    var body: some Scene {
        WindowGroup { ContentView() }
    }
}

App foreground/background kab gaya

SceneDelegate ke sceneDidBecomeActive ki jagah scenePhase use karo:

@main
struct MyApp: App {
    @Environment(\.scenePhase) private var phase

    var body: some Scene {
        WindowGroup { ContentView() }
            .onChange(of: phase) { _, newPhase in
                if newPhase == .active     { print("App active") }
                if newPhase == .background { print("Background mein gaya") }
            }
    }
}

Screen aane par code chalana (viewDidLoad / viewWillAppear)

Text("Home")
    .onAppear { print("Screen dikha") }      // ~ viewWillAppear
    .onDisappear { print("Screen gaya") }    // ~ viewDidDisappear
    .task { await loadData() }               // async API call, screen jaate hi cancel

2. View kya hota hai

SwiftUI mein har screen aur har chhoti cheez ek View hai: ek struct jiske body mein likha hota hai ki UI kaisa dikhega. UIViewController + UIView dono ka kaam yahi ek struct karta hai.

struct ProfileCard: View {          // 1. struct, class nahi
    let name: String                 // 2. bahar se data aaya (init jaisa)

    var body: some View {            // 3. yahi UI hai
        VStack {
            Image(systemName: "person.circle.fill")
                .font(.system(size: 60))
            Text(name)
                .font(.title2)
                .bold()
        }
        .padding()                   // 4. modifiers
        .background(.blue.opacity(0.1))
        .clipShape(RoundedRectangle(cornerRadius: 16))
    }
}

// Use karna: ProfileCard(name: "Rahul")

Teen baatein yaad rakhni hain:

  • Struct hai, class nahi. View bahut halka hota hai. SwiftUI isko baar-baar dobara banata hai, isliye isme heavy kaam (API call) body ke andar mat likho.
  • Modifiers order se chalte hain. .padding().background(.blue) aur .background(.blue).padding() alag dikhte hain. Pehle mein padding ke saath background bada hota hai, doosre mein background sirf text jitna hota hai aur padding bahar khali jagah banti hai.
  • Chhote views banao. UIKit mein ek bada ViewController hota tha. SwiftUI mein screen ko chhote views (ProfileCard, LoginButton) mein todo aur jodo.
// Modifier order ka farak
Text("A").padding().background(.yellow)   // yellow box bada, text ke charo taraf
Text("B").background(.yellow).padding()   // yellow sirf text par, bahar khali jagah

3. Layout: constraints ki jagah Stack + Spacer

SwiftUI mein constraints nahi likhte. Views ko Stack mein rakhte ho, aur SwiftUI ka default rule hai: content utni hi jagah leta hai jitni use chahiye, aur poora group screen ke beech mein aa jaata hai. Jagah bharni ho ya cheez ko kinare dhakelna ho, to Spacer() lagate ho.

Teen stacks

Stack Kya karta hai UIKit mein
VStack Upar se neeche Vertical UIStackView
HStack Left se right Horizontal UIStackView
ZStack Ek ke upar ek (layers) addSubview se overlap

Default kaisa dikhta hai (Spacer ke bina)

VStack {
    Text("Welcome").font(.largeTitle)
    Text("Login karke aage badho")
    Button("Login") { }
        .buttonStyle(.borderedProminent)
}

Isme koi constraint nahi hai, phir bhi teeno cheezein screen ke bilkul beech mein aa jaati hain. Inke beech chhota default gap (lagbhag 8 point) hota hai, aur stack ki chaudai sabse chaude child jitni hoti hai.

Spacer lagane ke baad

Spacer() ek khali view hai jo jitni jagah bachi hai, saari le leta hai. Stack mein jahan lagao, wahan se cheezein door dhakel deta hai.

// B: content upar, baaki jagah neeche khali
VStack {
    Text("Welcome")
    Text("Login karke aage badho")
    Button("Login") { }
    Spacer()                // neeche dhakelta hai
}

// C: button neeche chipak gaya, text upar
VStack {
    Text("Welcome")
    Text("Login karke aage badho")
    Spacer()                // beech ki saari jagah
    Button("Login") { }
}

// D: do Spacer = jagah barabar baat li
VStack {
    Spacer()
    Text("Welcome")
    Spacer()
    Button("Login") { }
}

Rule: ek stack mein jitne Spacer, bachi hui jagah utne barabar hisson mein baat jaati hai. HStack mein bhi same: HStack { Text("Left"); Spacer(); Text("Right") } se ek left aur ek right kinare par chala jaata hai.

Spacing khud set karna

VStack(spacing: 20) { ... }          // har child ke beech 20pt (default ~8)
VStack(spacing: 0) { ... }           // bilkul chipke hue

Spacer().frame(height: 40)           // fixed 40pt ka gap (constant constraint jaisa)
Spacer(minLength: 16)                // kam se kam 16pt, zyada jagah ho to badhega

Padding = margin/inset

Text("Hello")
    .padding()                       // charo taraf ~16pt (system default)
    .padding(.horizontal, 24)        // sirf left + right 24pt
    .padding(.top, 50)               // sirf upar 50pt

Alignment: left, right, center

VStack(alignment: .leading) {        // stack ke andar sab left aligned
    Text("Naam")
    Text("Bahut lamba address yahan")
}

Text("Left mein")
    .frame(maxWidth: .infinity, alignment: .leading)   // full width, text left

Button("Login") { }
    .frame(maxWidth: .infinity)      // button poori chaudai le
    .frame(height: 50)               // fixed height

.frame(maxWidth: .infinity) ka matlab hai "leading aur trailing dono constraint 0 par lagao". Constraints wale dimaag ke liye yeh sabse kaam ki line hai.

Safe area

SwiftUI content default mein safe area ke andar rakhta hai (notch aur home indicator se bach ke). Background poori screen par chahiye to:

ZStack {
    Color.blue.ignoresSafeArea()     // background edge to edge
    Text("Content safe area mein")
}

Ek perfect login screen layout

struct LoginLayout: View {
    var body: some View {
        VStack(spacing: 16) {
            Spacer()                                  // upar ki khali jagah

            Image(systemName: "lock.shield.fill")
                .font(.system(size: 70))
                .foregroundStyle(.blue)
            Text("Welcome Back").font(.largeTitle).bold()

            Spacer().frame(height: 24)                // logo aur form ke beech fixed gap

            TextField("Email", text: .constant(""))
                .textFieldStyle(.roundedBorder)
            SecureField("Password", text: .constant(""))
                .textFieldStyle(.roundedBorder)

            Spacer()                                  // form ko upar, button ko neeche

            Button("Login") { }
                .frame(maxWidth: .infinity, minHeight: 50)
                .background(.blue)
                .foregroundStyle(.white)
                .clipShape(RoundedRectangle(cornerRadius: 12))
        }
        .padding(.horizontal, 24)                     // left/right margin
        .padding(.bottom, 16)
    }
}

Do Spacer hain, to bachi hui jagah upar aur form ke neeche barabar batti hai. Isliye har iPhone size par screen balanced dikhti hai, alag constraint likhne ki zaroorat nahi.

4. Navigation: button click se next screen

Pehle screen ko NavigationStack mein lapeto (yeh UINavigationController hai). Phir NavigationLink tap karne par next screen push hoti hai. pushViewController ya segue likhne ki zaroorat nahi.

Tarika 1: NavigationLink (sabse simple)

struct HomeView: View {
    var body: some View {
        NavigationStack {                      // = UINavigationController
            VStack(spacing: 20) {
                Text("Home Screen")

                NavigationLink("Detail par jao") {   // tap = push
                    DetailView(message: "Home se aaya hoon")
                }
                .buttonStyle(.borderedProminent)
            }
            .navigationTitle("Home")           // = self.title
        }
    }
}

struct DetailView: View {
    let message: String                        // data pass hua (init se)

    var body: some View {
        Text(message)
            .navigationTitle("Detail")
            // Back button khud aata hai, swipe-back bhi
    }
}

Tarika 2: Button se, condition check karke (login ke baad jaana)

Kabhi button dabane par pehle kuch check karna hota hai (jaise password sahi hai ya nahi). Tab ek Bool state rakho aur .navigationDestination(isPresented:) lagao:

struct LoginView: View {
    @State private var goToHome = false
    @State private var password = ""

    var body: some View {
        NavigationStack {
            VStack {
                SecureField("Password", text: $password)
                    .textFieldStyle(.roundedBorder)

                Button("Login") {
                    if password == "1234" {     // check pass hua
                        goToHome = true         // ab navigate karo
                    }
                }
            }
            .padding()
            .navigationDestination(isPresented: $goToHome) {
                HomeView()
            }
        }
    }
}

Tarika 3: List se, data ke hisab se (value-based)

struct FruitList: View {
    let fruits = ["Aam", "Kela", "Seb"]

    var body: some View {
        NavigationStack {
            List(fruits, id: \.self) { fruit in
                NavigationLink(fruit, value: fruit)   // sirf value bhejo
            }
            .navigationDestination(for: String.self) { fruit in
                Text("Tumne \(fruit) chuna")          // value ke hisab se screen
            }
            .navigationTitle("Fruits")
        }
    }
}

Code se wapas jaana (popViewController / dismiss)

struct DetailView: View {
    @Environment(\.dismiss) private var dismiss

    var body: some View {
        Button("Wapas jao") {
            dismiss()                 // = popViewController / dismiss(animated:)
        }
    }
}

Modal (present) karna: sheet aur fullScreenCover

struct SettingsButton: View {
    @State private var showSettings = false

    var body: some View {
        Button("Settings kholo") { showSettings = true }
            .sheet(isPresented: $showSettings) {        // neeche se card
                SettingsView()
            }
            // .fullScreenCover(isPresented: $showSettings) { ... }  // poori screen
    }
}

Yaad rakho: NavigationStack sirf ek baar, sabse bahar wali screen par lagta hai. Detail screen ke andar dobara mat lagana, warna do navigation bar ban jaate hain.

5. Property wrappers: data badla to UI khud badlega

SwiftUI mein label.text = "..." jaisa UI ko haath se update nahi karte. Data ko ek property wrapper (@State waghera) mein rakhte ho. Data badla, to SwiftUI body dobara chalata hai aur screen khud update ho jaati hai.

Wrapper Kab use karo Example
@State Is screen ka apna chhota data Toggle on/off, TextField text, counter
@Binding Parent ka @State child ko dena, taaki child badal sake Custom toggle/textfield view
@Observable class + @State Bada data ya logic (ViewModel), iOS 17+ User profile, API se aayi list
@Environment System ki values ya poori app mein share hua object dismiss, colorScheme, shared ViewModel
@AppStorage Chhoti setting jo app band hone ke baad bhi rahe Dark mode, "logged in hai?" (UserDefaults)

@State: screen ka apna data

struct CounterView: View {
    @State private var count = 0        // hamesha private rakho

    var body: some View {
        VStack(spacing: 16) {
            Text("Count: \(count)")     // count badla = Text khud badla
                .font(.largeTitle)
            Button("+1") { count += 1 }  // label update ka code nahi likha
        }
    }
}

@Binding: child ko parent ka data badalne do

$ lagane se binding banti hai, yani us data ka "reference". Child usko padh bhi sakta hai aur badal bhi sakta hai.

struct ParentView: View {
    @State private var isOn = false

    var body: some View {
        VStack {
            Text(isOn ? "Light ON" : "Light OFF")
            LightSwitch(isOn: $isOn)          // $ = binding bhejo
        }
    }
}

struct LightSwitch: View {
    @Binding var isOn: Bool                  // parent ka data, copy nahi

    var body: some View {
        Button(isOn ? "Band karo" : "Chalu karo") {
            isOn.toggle()                    // parent ka Text bhi badlega
        }
    }
}

UIKit mein yeh kaam delegate ya closure se hota tha.

@Observable: ViewModel (MVVM)

import Observation

@Observable
class ProfileViewModel {
    var name = "Guest"
    var isLoading = false

    func load() async {
        isLoading = true
        try? await Task.sleep(for: .seconds(1))  // API call jaisa
        name = "Rahul Sharma"
        isLoading = false
    }
}

struct ProfileView: View {
    @State private var vm = ProfileViewModel()   // screen ViewModel ka owner

    var body: some View {
        VStack {
            if vm.isLoading { ProgressView() }
            else { Text(vm.name).font(.title) }
        }
        .task { await vm.load() }                // screen aate hi load
    }
}

Purane code (iOS 13–16) mein yahi kaam class VM: ObservableObject + @Published var + @StateObject se hota hai. Project mein dikhe to samajh lena same cheez hai.

@Environment aur @AppStorage

struct SettingsView: View {
    @Environment(\.dismiss) private var dismiss        // screen band karna
    @Environment(\.colorScheme) private var scheme     // light/dark
    @AppStorage("isDarkMode") private var isDarkMode = false   // UserDefaults mein save

    var body: some View {
        Form {
            Toggle("Dark Mode", isOn: $isDarkMode)
            Text("Abhi: \(scheme == .dark ? "Dark" : "Light")")
            Button("Close") { dismiss() }
        }
    }
}

6. Chhota app banao: "My Tasks"

Yeh chhota app upar ke saare concepts ek saath use karta hai: @main se start, Login screen, login ke baad Home list, tap par Detail, aur + dabane par sheet. Naya Xcode project banao (Interface: SwiftUI, naam MyTasks) aur yeh files daalo. Iska poora code screens ke saath SwiftUI Basics page (images wala) mein bhi hai.

App ka flow

  1. App khula → TaskApp (@main) dekhta hai isLoggedIn true hai ya false.
  2. False → LoginView dikhta hai. Login dabaya → isLoggedIn = true → SwiftUI khud HomeView par switch kar deta hai.
  3. HomeView mein task par tap → NavigationLink → DetailView push hota hai.
  4. Detail mein "Done mark karo" → store update → dismiss() → wapas Home, jahan list khud update dikhegi.
  5. Home par + → AddTaskView sheet. Save → naya task list mein.
  6. Logout → isLoggedIn = false → wapas Login. App band karke kholo to login yaad rehta hai (@AppStorage).

File 1: TaskApp.swift (entry point)

import SwiftUI

@main
struct TaskApp: App {
    @AppStorage("isLoggedIn") private var isLoggedIn = false   // UserDefaults
    @State private var store = TaskStore()                     // poori app ka data

    var body: some Scene {
        WindowGroup {
            if isLoggedIn {
                HomeView()
                    .environment(store)    // store saare child screens ko mila
            } else {
                LoginView()
            }
        }
    }
}

File 2: TaskStore.swift (data + logic)

import Foundation
import Observation

struct TaskItem: Identifiable, Hashable {
    let id = UUID()
    var title: String
    var isDone = false
}

@Observable
class TaskStore {
    var tasks: [TaskItem] = [
        TaskItem(title: "SwiftUI seekho"),
        TaskItem(title: "Spacer samjho"),
        TaskItem(title: "Navigation try karo")
    ]

    func add(_ title: String) {
        tasks.append(TaskItem(title: title))
    }

    func toggle(_ task: TaskItem) {
        if let i = tasks.firstIndex(where: { $0.id == task.id }) {
            tasks[i].isDone.toggle()
        }
    }
}

File 3: LoginView.swift

import SwiftUI

struct LoginView: View {
    @AppStorage("isLoggedIn") private var isLoggedIn = false
    @State private var email = ""
    @State private var password = ""
    @State private var showError = false

    var body: some View {
        VStack(spacing: 16) {
            Spacer()

            Image(systemName: "checklist")
                .font(.system(size: 70))

                .keyboardType(.emailAddress)

                .textFieldStyle(.roundedBorder)

            Button {
                if email.isEmpty || password.count < 4 {
                    showError = true
                } else {
                    isLoggedIn = true          // root khud HomeView ban jaayega
                }
            } label: {
                Text("Login").bold()
                    .frame(maxWidth: .infinity, minHeight: 50)
            }
            .buttonStyle(.borderedProminent)

        .padding(.horizontal, 24)
        .padding(.bottom, 16)
        .alert("Email aur 4+ digit password daalo", isPresented: $showError) {
            Button("OK") { }
        }
    }
}

File 4: HomeView.swift

import SwiftUI

struct HomeView: View {
    @Environment(TaskStore.self) private var store
    @AppStorage("isLoggedIn") private var isLoggedIn = true
    @State private var showAdd = false

    var body: some View {
        NavigationStack {
            List(store.tasks) { task in
                NavigationLink(value: task) {              // tap = Detail push
                    HStack {
                        Image(systemName: task.isDone ? "checkmark.circle.fill" : "circle")
                            .foregroundStyle(task.isDone ? .green : .gray)
                        Text(task.title)
                    }
                }
            }
            .navigationTitle("My Tasks")
            .navigationDestination(for: TaskItem.self) { task in
                DetailView(task: task)
            }
            .toolbar {
                ToolbarItem(placement: .topBarLeading) {
                    Button("Logout") { isLoggedIn = false }
                }
                ToolbarItem(placement: .topBarTrailing) {
                    Button("Add", systemImage: "plus") { showAdd = true }
                }
            }
            .sheet(isPresented: $showAdd) {
                AddTaskView()
                    .environment(store)
            }
        }
    }
}

File 5: DetailView.swift aur AddTaskView.swift

import SwiftUI

struct DetailView: View {
    @Environment(TaskStore.self) private var store
    @Environment(\.dismiss) private var dismiss
    let task: TaskItem

    var body: some View {
        VStack(spacing: 20) {
            Image(systemName: task.isDone ? "checkmark.seal.fill" : "hourglass")
                .font(.system(size: 80))
                .foregroundStyle(task.isDone ? .green : .orange)
            Text(task.title)
                .font(.title).bold()
            Text(task.isDone ? "Ho gaya" : "Abhi baaki hai")
                .foregroundStyle(.secondary)

            Spacer()                                       // button neeche

            Button(task.isDone ? "Wapas pending karo" : "Done mark karo") {
                store.toggle(task)
                dismiss()                                  // wapas Home
            }
            .buttonStyle(.borderedProminent)
            .controlSize(.large)
        }
        .padding(24)
        .navigationTitle("Detail")
        .navigationBarTitleDisplayMode(.inline)
    }
}

struct AddTaskView: View {
    @Environment(TaskStore.self) private var store
    @Environment(\.dismiss) private var dismiss
    @State private var title = ""

    var body: some View {
        NavigationStack {                                  // sheet ka apna nav bar
            Form {
                TextField("Task ka naam", text: $title)
            }
            .navigationTitle("Naya Task")
            .toolbar {
                ToolbarItem(placement: .cancellationAction) {
                    Button("Cancel") { dismiss() }
                }
                ToolbarItem(placement: .confirmationAction) {
                    Button("Save") {
                        store.add(title)
                        dismiss()
                    }
                    .disabled(title.isEmpty)
                }
            }
        }
    }
}

Sheet ek alag modal hai, isliye uske andar apna NavigationStack lagana theek hai. "Ek hi NavigationStack" wala rule push hone wali screens ke liye hai.

  • Detail screen par task delete karne ka button add karo
  • Home list mein swipe-to-delete lagao (.onDelete)
  • Settings screen banao jisme dark mode toggle ho (@AppStorage)

UILabel Text

UITableView / UICollectionView List / LazyVGrid

Storyboard / XIB #Preview (code hi UI hai)

Common galtiyan

  • Har screen mein NavigationStack. Sirf root par lagao, warna double navigation bar aata hai.
  • @State ko private na rakhna. @State hamesha private var ho. Bahar se data chahiye to let ya @Binding use karo.
  • body ke andar API call. body baar-baar chalta hai. API call .task { } mein karo.
  • Spacer ka zyada use. Fixed gap chahiye to VStack(spacing:) ya .padding. Spacer tab, jab cheez ko kinare tak dhakelna ho.
  • Modifier order bhool jaana. .padding().background() aur .background().padding() alag dikhte hain. Background ko padding ke saath bada chahiye to padding pehle lagao.
  • Frame se fixed width dena. .frame(width: 375) mat likho. .frame(maxWidth: .infinity) + .padding har iPhone par sahi dikhta hai.
